Sign in

Dashboard sign-in sets the session cookie on this origin and lands on the htmx dashboard (overview, region choice, devices, account deletion); the buttons below then act through the same cookie. App sign-in uses the loopback redirect flow and keeps the bearer token and storage refresh token in this tab: open this page at http://127.0.0.1:<port>/dev for it, since only loopback IPs are allowed redirect targets. Deleting the account needs a sign-in within 10 minutes; "sign in again" sends max_age=0 to the provider (the dashboard one refreshes this browser's session and returns to delete).

Storage

Rotation: re-presenting the previous token returns the same successor until that successor is exchanged (a lost response); after that it is reuse and signs the session out. Two concurrent exchanges get one successor.

Upload with the access token: curl -H "Authorization: Bearer <access_token>" --data-binary @file <endpoint>/blobs, then paste the receipt below.

Objects

Vault key

Key material for the collection above. With the recovery envelope unticked, a put deletes any stored one. Rotate sends the last key_updated_at seen as previous_key_updated_at.

Pairing

The new device opens a pairing and polls; the unlocked device (another tab signed in as the same user, or this one) posts the vault key sealed to the pairing's public key. The server never opens the ciphertext, so any string stands in for it here. A pairing lasts 5 minutes, and the first poll that returns the key deletes it.

Jobs

Runs a storage job now on this replica, outside its schedule and lock. Reconciliation deletes keys older than 48h that the ledger does not know; now (RFC 3339) shifts its clock, and an empty user means every prefix.
